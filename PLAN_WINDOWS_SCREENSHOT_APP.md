# План микроприложения для скриншотов Windows

## 1. Цель

Создать максимально быстрое и лёгкое нативное приложение для Windows 10/11, которое повторяет основной рабочий процесс «Скриншотов в Яндекс Диске», но работает полностью локально:

1. Приложение постоянно находится в системном трее и ожидает горячую клавишу.
2. По горячей клавише захватывает область, окно, монитор или весь виртуальный рабочий стол.
3. Сразу открывает снимок в простом редакторе.
4. Позволяет добавить стрелки, текст, фигуры, маркер, размытие и выполнить обрезку.
5. Копирует результат в буфер обмена, сохраняет локально или передаёт через стандартное меню Windows «Поделиться».

Приложение не использует аккаунты, облачные диски, собственный сервер, аналитику и синхронизацию.

## 2. Важное ограничение

Функцию Яндекс Диска «сохранить в облаке и получить публичную ссылку» невозможно повторить без внешнего хранилища или собственного сервера.

В локальной версии кнопка **«Поделиться»** должна:

- сформировать итоговый PNG во временной папке приложения;
- открыть стандартную панель «Поделиться» Windows;
- передать файл выбранному установленному приложению;
- удалить временный файл позже, при следующем запуске или штатной очистке.

Приложение само никуда изображение не загружает. Наличие доступных получателей зависит от установленных в Windows приложений.

## 3. Выбранный технический стек

### Основной вариант

- язык: **C++20**;
- интерфейс и системная интеграция: **Win32 API**;
- отрисовка редактора: **Direct2D**;
- текст: **DirectWrite**;
- чтение и запись PNG/JPEG: **Windows Imaging Component (WIC)**;
- захват экрана: **DXGI Desktop Duplication**, с резервным захватом через GDI для несовместимых систем;
- сборка: **CMake + Visual Studio Build Tools**;
- установщик: небольшой **MSIX** или обычный подписанный установщик без дополнительных сред выполнения.

### Почему выбран этот вариант

Нативное приложение не требует Electron, Chromium, WebView, .NET Runtime или отдельного фонового сервиса. Оно может запускаться одним процессом, использовать системные библиотеки Windows и занимать минимум оперативной памяти в режиме ожидания.

Rust теоретически также подходит, но для задачи, тесно связанной с Win32, Direct2D, WIC, буфером обмена и системным треем, C++ даёт более прямой доступ к Windows API и меньше промежуточных зависимостей.

## 4. Целевые показатели

Это критерии приёмки, а не заранее гарантированные результаты:

| Показатель | Цель |
|---|---:|
| Память в трее без открытого редактора | до 20 МБ |
| Загрузка CPU в ожидании | около 0%, без периодического опроса |
| Время появления режима выделения после хоткея | до 100 мс на обычном ПК |
| Время открытия редактора после выделения | до 150 мс для экрана 4K |
| Размер установленного приложения | до 15 МБ без символов отладки |
| Фоновая сеть | отсутствует |
| Количество фоновых процессов | один |

Если Direct2D или видеодрайвер недоступен, допустим более медленный резервный режим. Он не должен влиять на обычный запуск.

## 5. Состав приложения

Приложение состоит из одного EXE и логически разделено на модули:

1. **TrayHost** — трей, глобальные горячие клавиши, настройки и запуск захвата.
2. **CaptureEngine** — получение пикселей с одного или нескольких мониторов.
3. **SelectionOverlay** — полноэкранная полупрозрачная поверхность выбора области или окна.
4. **EditorWindow** — окно редактора.
5. **DocumentModel** — исходное изображение, объекты разметки, Undo/Redo и обрезка.
6. **Renderer** — вывод изображения и объектов через Direct2D.
7. **ExportService** — PNG/JPEG, буфер обмена, печать и Windows Share.
8. **SettingsStore** — локальные настройки пользователя.

Отдельная служба Windows не нужна.

## 6. Поведение в системном трее

После запуска приложение:

- создаёт значок в системном трее;
- регистрирует глобальные горячие клавиши через `RegisterHotKey`;
- не держит скрытое тяжёлое окно редактора;
- ожидает системные события без циклического опроса;
- при необходимости может запускаться вместе с Windows.

Меню значка в трее:

- Снимок области;
- Снимок области и поделиться;
- Снимок окна;
- Снимок активного монитора;
- Снимок всех мониторов;
- Открыть изображение в редакторе;
- Открыть папку сохранения;
- Настройки;
- Выход.

Автозапуск выключен при первой установке и включается пользователем.

## 7. Горячие клавиши

Стандартный набор повторяет привычную логику Яндекс Диска:

| Действие | По умолчанию |
|---|---|
| Выбрать область | `Ctrl + Shift + 1` |
| Выбрать область и затем поделиться | `Ctrl + Shift + 2` |
| Активный монитор | `Ctrl + Shift + 3` |
| Выбрать окно | `Ctrl + Shift + 4` |
| Активный монитор | `Print Screen` |
| Активное окно | `Alt + Print Screen` |

Все сочетания можно:

- переназначить;
- отключить по отдельности;
- временно отключить одной общей настройкой.

Если сочетание занято другим приложением, программа не должна молча перехватывать его. В настройках отображается предупреждение «Сочетание уже используется».

## 8. Сценарии захвата

### 8.1. Захват области

После хоткея приложение сначала делает мгновенный снимок всех мониторов, затем показывает этот зафиксированный кадр поверх рабочего стола. Это исключает изменения содержимого во время выделения.

Поведение:

1. Курсор меняется на перекрестие.
2. Весь экран слегка затемняется.
3. Пользователь зажимает левую кнопку мыши и тянет прямоугольник.
4. Внутри выбранной области показывается исходное изображение без затемнения.
5. Рядом с рамкой отображаются размеры в физических пикселях, например `1280 × 720`.
6. После отпускания кнопки область сразу передаётся в редактор.
7. `Esc` отменяет захват.
8. Правая кнопка мыши также отменяет захват.

Выделение всегда прямоугольное. Произвольная форма захвата не нужна.

### 8.2. Захват окна

После хоткея приложение показывает зафиксированный рабочий стол. Окно под курсором подсвечивается рамкой.

Правила:

- учитываются реальные границы окна с учётом DWM;
- невидимые, свёрнутые и системные служебные окна пропускаются;
- окно самого скриншотера не должно попадать в список;
- щелчок захватывает выбранное окно;
- `Esc` отменяет операцию.

По умолчанию сохраняется видимая прямоугольная область окна вместе с его рамкой и тенью. Перекрывающие его окна не попадают в результат, если Windows позволяет получить содержимое окна; при невозможности используется снимок фактически видимой области.

### 8.3. Активный монитор

Захватывается монитор, на котором находится курсор в момент нажатия хоткея. Это поведение однозначнее, чем попытка определять «главное» окно пользователя.

### 8.4. Все мониторы

Создаётся единое изображение виртуального рабочего стола. Расположение мониторов и пустые промежутки между ними сохраняются.

### 8.5. Масштабирование Windows

Приложение объявляется Per-Monitor DPI Aware V2. Координаты выделения переводятся в физические пиксели отдельно для каждого монитора. Захват не должен обрезаться или смещаться при комбинации, например, 100% на одном экране и 150% на другом.

## 9. Модель редактирования

Редактор работает **неразрушающе** до момента экспорта:

- исходный снимок хранится как неизменяемый bitmap;
- стрелки, текст, фигуры и линии хранятся как векторные объекты;
- маркер хранится как набор сглаженных траекторий;
- размытие хранится как область и параметры эффекта;
- обрезка хранится как отдельный прямоугольник документа;
- итоговая растеризация выполняется только при копировании, сохранении, печати или передаче другому приложению.

Это позволяет выбирать ранее добавленные объекты, менять их, удалять и корректно выполнять Undo/Redo без ухудшения качества исходного изображения.

### Общие правила объектов

- последний созданный объект находится поверх предыдущих;
- щелчок по объекту выбирает его;
- выбранный объект получает рамку и управляющие точки;
- перетаскивание внутри объекта перемещает его;
- управляющие точки меняют размер или направление;
- `Delete` и `Backspace` удаляют выбранный объект;
- стрелки клавиатуры перемещают объект на 1 пиксель;
- `Shift` + стрелка перемещает объект на 10 пикселей;
- `Ctrl + C`, `Ctrl + X`, `Ctrl + V` работают с объектами;
- если объект не выбран, `Ctrl + C` копирует готовое изображение целиком;
- щелчок по пустому месту снимает выделение.

## 10. Интерфейс редактора

Интерфейс повторяет логику представленного примера, но без облачных элементов.

### Верхнее меню

- **Файл:** открыть, сохранить, сохранить как, печать, закрыть;
- **Правка:** отменить, повторить, вырезать, копировать, вставить, удалить;
- **Вид:** увеличить, уменьшить, 100%, вписать в окно;
- **Справка:** горячие клавиши, версия приложения.

### Основная панель инструментов

- Стрелки;
- Текст;
- Фигуры;
- Маркер;
- Размытие;
- Обрезать;
- Undo;
- Redo.

### Контекстная панель

Вторая строка меняется в зависимости от активного инструмента. На ней показываются только относящиеся к нему параметры:

- вариант инструмента;
- толщина;
- цвет;
- прозрачность или интенсивность, если применимо.

### Нижняя панель

Слева:

- текущий масштаб в процентах;
- уменьшить;
- ползунок масштаба;
- увеличить.

Справа:

- Копировать;
- Сохранить;
- Поделиться.

## 11. Точное поведение инструментов обработки

Ниже зафиксировано предлагаемое поведение. Этот раздел предназначен для согласования до начала разработки.

### 11.1. Стрелки

После выбора инструмента контекстная панель показывает:

- широкая заполненная стрелка;
- тонкая контурная стрелка;
- изогнутая пунктирная стрелка;
- толщина: тонкая, средняя, толстая;
- цвет из общей палитры.

Создание прямой стрелки:

1. Нажать в точке начала.
2. Тянуть курсор к точке назначения.
3. Отпустить кнопку — наконечник находится в точке отпускания.

Удержание `Shift` фиксирует направление с шагом 45°. После создания начало и конец остаются отдельными управляющими точками. Их можно перемещать.

Толщина линии и размер наконечника меняются пропорционально. Цвет применяется ко всей стрелке.

Изогнутая пунктирная стрелка создаётся тем же перетаскиванием между началом и концом. После отпускания она получает стандартную плавную дугу. У неё три управляющие точки: начало, конец и кривизна. Перемещение средней точки меняет изгиб. Линия пунктирная, наконечник сплошной.

### 11.2. Текст

Создание:

1. Пользователь щёлкает в нужной точке.
2. Появляется текстовое поле с кареткой.
3. Текст вводится сразу поверх изображения.
4. `Ctrl + Enter` или щелчок вне поля завершает ввод.
5. `Esc` отменяет создание пустого объекта или возвращает прежний текст при редактировании.

Параметры соответствуют описанию Яндекса:

- три заранее заданных варианта шрифта;
- цвет текста из общей палитры;
- тип фона: без фона, светлая подложка или тёмная подложка.

Для первой реализации три варианта шрифта задаются как системный нейтральный, системный полужирный и рукописный. Конкретные гарнитуры должны входить в Windows или поставляться легально вместе с приложением; загрузка шрифтов из интернета не допускается.

После завершения ввода вокруг текста можно показать рамку. Перетаскивание углов пропорционально меняет размер всей надписи, как в редакторе Яндекса. Перетаскивание боковых точек меняет ширину текстового блока и перенос строк. Двойной щелчок снова включает редактирование текста.

Сложное форматирование отдельных символов, тени и контуры не входят в первую версию.

### 11.3. Фигуры

Поддерживаются четыре фигуры, соответствующие смыслу панели примера:

- прямоугольник;
- эллипс;
- прямая линия;
- звезда.

Фигура создаётся перетаскиванием от одного угла ограничивающего прямоугольника к другому.

Параметры:

- толщина контура: тонкая, средняя, толстая;
- цвет контура;
- без заливки.

При удержании `Shift`:

- прямоугольник становится квадратом;
- эллипс становится кругом;
- линия фиксируется с шагом 45°;
- звезда сохраняет равные пропорции.

После создания фигуру можно перемещать и менять её размер. Поворот фигур в первую версию не входит.

### 11.4. Маркер

Маркер — свободная полупрозрачная линия, предназначенная для выделения текста и участков изображения.

Поведение:

1. Пользователь зажимает левую кнопку мыши.
2. Приложение записывает траекторию движения курсора.
3. Точки траектории сглаживаются, чтобы линия не выглядела ломаной.
4. После отпускания создаётся один объект-маркер.

Параметры:

- толщина: тонкая, средняя, толстая;
- цвет;
- фиксированная прозрачность 45%.

Линия имеет закруглённые концы. Пересечение одного и того же места несколькими штрихами визуально усиливает цвет, как у физического маркера. Созданный штрих можно выбрать, переместить или удалить целиком; редактирование отдельных точек траектории не требуется.

### 11.5. Размытие

Размытие предназначено для скрытия текста, лиц, номеров, реквизитов и других частей исходного снимка.

Предлагаемое поведение:

1. Пользователь перетаскиванием создаёт прямоугольную область.
2. Внутри области применяется сильное размытие по Гауссу.
3. Результат виден сразу при выделении.
4. После создания область можно переместить и изменить её размер.

Параметры:

- постоянная степень размытия, подобранная так, чтобы мелкий текст нельзя было прочитать;
- прямоугольная форма области;
- без произвольной кисти;
- без отдельной настройки силы в первой версии.

Размытие применяется только к исходному снимку и к вставленным растровым изображениям, находящимся ниже него в порядке слоёв. Стрелки, текст и фигуры поверх области остаются резкими.

При экспорте эффект необратимо встраивается в итоговое изображение. Важно: простое размытие хуже подходит для гарантированного сокрытия крупных букв и цифр, чем сплошная заливка. Но сплошной редактирующий блок не добавляется, потому что его нет в исходном интерфейсе и задача — повторить поведение редактора.

### 11.6. Обрезка

Обрезка изменяет границы документа, но не создаёт новый снимок экрана.

После включения инструмента:

1. Текущее изображение показывается целиком.
2. Вокруг рабочей области появляется рамка с восемью управляющими точками.
3. Затемняется часть, которая будет удалена.
4. Пользователь двигает края, углы или рисует новую рамку.
5. `Enter` или кнопка «Применить» подтверждает обрезку.
6. `Esc` отменяет текущую операцию.

Обрезка не удаляет данные немедленно. Команда Undo возвращает прежние границы и все объекты за ними. При подтверждённом экспорте сохраняется только видимая область.

Объекты, частично выходящие за рамку, обрезаются по границе. Объекты полностью снаружи остаются в модели до закрытия документа, чтобы Undo мог их вернуть.

### 11.7. Вставка изображения

`Ctrl + V` проверяет буфер обмена:

- если там изображение, оно вставляется в центр видимой области отдельным объектом;
- если там путь к локальному изображению, файл открывается и вставляется;
- если активен текстовый объект и в буфере текст, текст вставляется в него;
- если текстового объекта нет, из текста создаётся новый текстовый объект.

Вставленное изображение можно перемещать и масштабировать. По умолчанию пропорции сохраняются; `Shift` временно разрешает свободное изменение пропорций.

### 11.8. Выбор и порядок объектов

Отдельной кнопки «Выбрать» в интерфейсе не требуется. После завершения рисования приложение автоматически переходит в нейтральный режим выбора. Повторный выбор инструмента позволяет рисовать несколько объектов подряд.

Порядок слоёв определяется временем создания. В первой версии специальных команд «на передний план» и «на задний план» нет.

### 11.9. Undo и Redo

История должна включать:

- создание и удаление объекта;
- перемещение;
- изменение размера;
- изменение текста;
- изменение цвета, толщины или интенсивности;
- вставку изображения;
- изменение рамки обрезки.

Непрерывное перетаскивание считается одной операцией, а не сотнями отдельных шагов. История ограничивается объёмом памяти, например 100 операциями или 64 МБ, в зависимости от того, что будет достигнуто раньше.

## 12. Масштаб и навигация

Масштаб влияет только на отображение в редакторе и не меняет разрешение итогового файла.

Поддерживаются:

- `Ctrl + колесо мыши`;
- кнопки `+` и `−`;
- ползунок;
- `Ctrl + +` и `Ctrl + -`;
- `Ctrl + 0` — 100%;
- команда «Вписать в окно».

При увеличенном масштабе изображение перемещается средней кнопкой мыши или `Space` + левая кнопка мыши. Масштабирование выполняется относительно позиции курсора.

## 13. Копирование

Кнопка **«Копировать»**:

1. Растеризует видимую после обрезки область в полном исходном разрешении.
2. Помещает изображение в Windows Clipboard в совместимом формате DIBV5.
3. Дополнительно помещает PNG-представление для программ, которые его поддерживают.
4. Не создаёт постоянный файл.

После успешной операции показывается ненавязчивое уведомление «Изображение скопировано».

## 14. Сохранение

При первом сохранении открывается системное окно выбора файла.

Поддерживаются:

- PNG — формат по умолчанию;
- JPEG — с настраиваемым качеством, по умолчанию 92%;

Шаблон имени по умолчанию:

`Screenshot_YYYY-MM-DD_HH-mm-ss.png`

Настройки:

- папка сохранения по умолчанию;
- спрашивать путь каждый раз;
- формат;
- качество JPEG;
- шаблон имени;
- действие после сохранения: оставить редактор открытым или закрыть.

Автоматического фонового сохранения без команды пользователя по умолчанию нет.

## 15. Открытие существующего изображения

Редактор поддерживает PNG, JPEG, BMP и WebP, если декодер доступен через WIC.

Открыть файл можно:

- через меню «Файл → Открыть»;
- перетаскиванием файла в окно;
- запуском EXE с путём файла;
- через необязательную интеграцию «Открыть с помощью» в Проводнике.

Исходный файл не перезаписывается автоматически. Обычная команда «Сохранить» после открытия предлагает создать отдельный файл, пока пользователь явно не подтвердит перезапись.

## 16. Печать

Команда «Файл → Печать» открывает стандартный диалог печати Windows. Печатается итоговая видимая область с применёнными объектами и обрезкой.

Минимальные параметры:

- выбранный принтер;
- ориентация страницы;
- вписать в страницу без искажения пропорций;
- фактический размер, если изображение помещается.

Собственный сложный модуль вёрстки не нужен.

## 17. Настройки

Настройки хранятся локально в `%LocalAppData%\\LocalScreenshot\\settings.json` либо в реестре пользователя. Секретных данных в них нет.

Разделы:

1. Горячие клавиши.
2. Формат и папка сохранения.
3. Поведение после захвата.
4. Автозапуск.
5. Запоминание последнего цвета и толщины.
6. Включение или отключение системных уведомлений.

Настройки не синхронизируются и не отправляются в сеть.

## 18. Производительность и экономия ресурсов

Для достижения целевых показателей:

- не создавать окно редактора до первого снимка;
- не загружать кодеки и графические ресурсы в режиме ожидания;
- не использовать таймеры для проверки хоткеев;
- держать в трее только message loop и небольшую модель настроек;
- создавать GPU-ресурсы Direct2D лениво;
- не копировать полный bitmap при каждом изменении векторного объекта;
- кэшировать только уменьшенную версию для текущего масштаба;
- освобождать ресурсы снимка после закрытия редактора;
- выполнять кодирование PNG/JPEG в рабочем потоке, не блокируя интерфейс;
- исключить телеметрию, автообновление и сетевые библиотеки из первой версии.

## 19. Безопасность и конфиденциальность

- сетевых запросов нет;
- снимок до сохранения находится в памяти процесса;
- временный файл создаётся только для Windows Share;
- временные файлы хранятся в собственной папке и удаляются;
- приложение не ведёт историю снимков;
- содержимое буфера обмена не читается в фоне;
- приложение не требует прав администратора;
- захват защищённого DRM-контента и защищённых системных окон может вернуть чёрную область — это ограничение Windows, обходить его не нужно.

## 20. Поэтапная реализация

### Этап 1. Технический прототип захвата

- трей и один глобальный хоткей;
- снимок всех мониторов;
- overlay выбора прямоугольной области;
- корректная работа с разным DPI;
- вывод выбранного bitmap в тестовом окне.

Критерий: выделение появляется быстро и совпадает с реальными пикселями на двух мониторах с разным масштабом.

### Этап 2. Каркас редактора

- окно, меню, панели и canvas;
- масштабирование и перемещение canvas;
- DocumentModel;
- выбор, перемещение и удаление объектов;
- Undo/Redo.

Критерий: интерфейс остаётся отзывчивым на изображении 4K.

### Этап 3. Основные инструменты

- стрелки;
- текст;
- прямоугольник, эллипс, линия и звезда;
- маркер;
- палитра и три толщины.

Критерий: каждый объект после создания можно выбрать и изменить без повреждения исходного снимка.

### Этап 4. Размытие и обрезка

- интерактивная пикселизация;
- изменение размера области размытия;
- неразрушающая обрезка;
- корректный порядок растеризации.

Критерий: экспорт совпадает с предпросмотром в редакторе при любом масштабе.

### Этап 5. Вывод результата

- Clipboard;
- PNG/JPEG;
- системный диалог сохранения;
- печать;
- Windows Share;
- локальные уведомления.

### Этап 6. Полный захват и настройки

- захват окна;
- активный монитор;
- все мониторы;
- все горячие клавиши;
- диагностика конфликтов;
- автозапуск;
- открытие существующих изображений.

### Этап 7. Оптимизация и выпуск

- измерение времени каждого сценария;
- проверка утечек памяти;
- тестирование 100%, 125%, 150%, 175% и 200% DPI;
- тестирование нескольких мониторов с отрицательными координатами;
- проверка Windows 10 и Windows 11;
- подпись EXE и установщика;
- сборка x64 Release без отладочных компонентов.

## 21. Обязательные тесты

### Захват

- один монитор;
- два и три монитора;
- разные DPI и разрешения;
- монитор слева или выше основного;
- HDR-монитор;
- полноэкранное приложение;
- окно с тенью и без рамки;
- быстрое двойное нажатие хоткея;
- отмена через `Esc`.

### Редактор

- 4K и очень узкие изображения;
- сотня объектов;
- Unicode и русский текст;
- вставка большого изображения;
- Undo после перемещения, изменения текста и обрезки;
- объекты частично за рамкой crop;
- размытие под и над другими объектами;
- сохранение PNG с прозрачностью вставленных объектов;
- JPEG без альфа-канала.

### Система

- конфликт горячих клавиш;
- перезапуск Проводника Windows;
- выход из Windows с открытым редактором;
- отсутствие принтера;
- отсутствуют приложения для Windows Share;
- недостаточно места на диске;
- запрет записи в выбранную папку.

## 22. Что сознательно не включается

Чтобы приложение осталось маленьким и быстрым, в первую версию не входят:

- аккаунты и облачное хранилище;
- генерация публичных ссылок;
- запись видео и звука;
- OCR;
- захват прокручиваемой веб-страницы;
- история всех снимков;
- совместная работа;
- плагины;
- встроенный автоапдейтер;
- сложные фильтры;
- слои с отдельной панелью;
- произвольное вращение объектов;
- редактирование исходного файла без подтверждения.

## 23. Пункты, требующие проверки перед разработкой

Нужно подтвердить или исправить именно эти правила:

1. **Полный экран:** активный монитор под курсором, а не сразу все мониторы.
2. **Стрелки:** широкая заполненная, тонкая контурная и изогнутая пунктирная.
3. **Фигуры:** прямоугольник, эллипс, линия и звезда; все без заливки.
4. **Маркер:** свободное рисование, 45% прозрачности, наложение штрихов усиливает цвет.
5. **Размытие:** прямоугольная область с фиксированным сильным Gaussian Blur, без кисти и регулировки силы.
6. **Обрезка:** применяется по `Enter`, остаётся обратимой через Undo до закрытия документа.
7. **Режим инструментов:** после одного объекта автоматический возврат к выбору; повторное нажатие инструмента включает серию объектов.
8. **Поделиться:** стандартная панель Windows с локальным PNG, без получения ссылки.
9. **Сохранение:** по умолчанию показывать диалог выбора файла, без автоматического сохранения каждого снимка.
10. **Закрытие:** при несохранённых изменениях спрашивать подтверждение только тогда, когда результат не был ни сохранён, ни скопирован.

После согласования этого раздела архитектуру менять не потребуется: корректировки будут относиться главным образом к поведению инструментов и интерфейсу.
